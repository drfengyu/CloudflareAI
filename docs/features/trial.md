# 限时活动·三国讨逆传（v0.49.0）

以《三国演义》为线索的长线剧情 RPG：从涿郡起兵，沿线攻克八处地方，剧情走完才
出现下一处地名。战斗是回合制兵团战（兵力、计策、阵型、招降），城镇里整备、
编成、买卖装备。没有每日次数、没有限时——只有剧情推进。

- 前台：`/trial`（侧边栏入口「每日试炼」，页面标题「三国讨逆传」，活动中心默认展示）
- 后台：系统设置 → 「限时活动（每日试炼）」
- 配置键：`option.trial_config`（界面按字段拆成数字输入框，管理员不写 JSON）
- 引擎：`lib/trial/saga/`（存档归一、剧情数据、战斗 / 指令重放、行军结算）
- 渲染：`components/trial/renderer.ts`（城镇与战斗的像素 Canvas 场景）
- 客户端：`components/trial/game.tsx`（城镇交互、编成商店、回合战斗、行军续局）
- 账本：`topup.type = 17`（平定奖励与钱庄存金合并成一条正流水；钱庄换金记一条负流水。
  票价在券兑换 / 礼包时已按 type=15 记过支出，出城不再写负流水）
- 表：`trial_run`（迁移 `migrations/028_new_activity_games.sql`，沿用旧列：
  `questions` 存行军 JSON、`questionCount` = 节点数、`correct` = 已攻克节点数）

## 剧情推进

内部把八处地方编号为 `chapter = 0..7`，但界面上只出现地名与剧情：

| 序 | 城镇 | 剧情 | 首领 | 平定后入队 |
| --- | --- | --- | --- | --- |
| 0 | 涿郡 | 桃园起兵 · 讨伐黄巾 | 张角 | — |
| 1 | 陈留 | 汜水关 · 讨伐董卓 | 董卓 | — |
| 2 | 小沛 | 徐州风云 · 讨伐袁术 | 袁术 | 赵云 |
| 3 | 下邳 | 白门楼 · 讨伐吕布 | 吕布 | 张辽 |
| 4 | 延津 | 官渡之战 · 河北争锋 | 袁绍 | 诸葛亮 |
| 5 | 江夏 | 赤壁之战 · 孙刘联军 | 曹操 | 黄忠 |
| 6 | 涪城 | 入蜀之路 · 西川归心 | 刘璋 | 马超 |
| 7 | 五丈原 | 五丈原 · 秋风斜谷 | 司马懿 | 魏延 |

- 只有**走完当前地方的全部节点**（收兵时 `victory`）才会把存档推进到下一处；
  中途兵败不推进，可回城整备后再走。
- 没走到的地方在界面上只显示「？？？ / 未至」，剧情文本在进入该地时展示。
- 平定最后一处后 `campaignComplete` 为真，服务端拒绝再开新行军，界面显示「全剧终」。
- 存档（武将等级 / 装备 / 金币 / 已平定地方 / 图鉴）随最近一行的 `endSave` 延续，
  下次行军从该存档继续；已平定地方仍可重走练级，但**不再发平定奖励**。

## 一次行军

1. 点「从{城镇}出发」，按票价折成**整数张**扣当期试炼活动券（`payWithCoupon`；
   `runPriceCredits` 被 `snapCostToUnit` 吸到券价整数倍，不足 1 张按 1 张）。
2. 服务端按种子生成这一路节点：默认 5 段（`questionCount`，上限 7）——
   普通战、精英、末段首领；地名取自当前地方的 `stages`。
3. 城镇里可编成（5 人上阵 + 12 人后备）、换阵型、买卖装备与药品；
   军需帐用**活动券**买局内增益（秘药 / 兵符 / 虎符 / 风行符 / 战鼓 / 锦囊），
   只在这次行军有效，被动军需每次限一份，购买从下一步行动起生效；
   钱庄可用金币存 tcr、用 tcr 换金币（见下节）。
4. 战斗是五将回合制：
   - 每将每回合选 攻击 / 计策 / 防御 / 道具；计策有火计、回复、混乱、鼓舞，消耗计策点。
   - 阵型（鱼鳞 / 鹤翼 / 锋矢 / 方圆 / 长蛇）互相克制，改变攻防速。
   - 敌将兵力降到 35% 以下可招降；史实可降武将（含吕布、张辽等）通过概率检定入队，
     队伍满时进后备。
   - 战斗胜利得金币与经验，升级提升四维与兵力上限；全灭则兵败回城。
5. 收兵时服务端用种子重放全部指令，写回剧情存档并按**攻克节点数**命中档位发 tcr；
   只有平定当前地方才发，且全剧终后不再发。

## 钱庄兑换（v0.49.0）

金币与 tcr 双向兑换，规则写在 `lib/trial/saga/bank.ts`：

| 方向 | 比例 | 限制 | 到账时机 |
| --- | --- | --- | --- |
| 金币 → tcr | 100 金 = 1 tcr | 每次行军最多存 300 金（3 tcr） | 收兵结算时，与平定奖励合并成一条正流水 |
| tcr → 金币 | 1 tcr = 50 金 | 只扣有效期内临时余额，不动永久 cr | 即时，购买记录随行军重放进存档 |

- **为什么不是 1 金 = 10 tcr**：一趟 5 节点全清给 `255 + 110×地方序` 金币，
  1:10 就是 2550 ~ 10250 tcr；而一次出城只要 1 张券（5 cr）。半途收兵刷金也能换
  数千 tcr——等于无限印钞。
- **100:1 + 每趟封顶 3 tcr**：满一趟存金收益 ≤ 3 tcr，低于 5 cr 的出城成本，
  不构成刷金套利；对认真推剧情的玩家是「顺路的额外奖励」，占平定奖励的零头。
- **反向往返价差 2:1**（100 金换 1 tcr，1 tcr 换回 50 金）：来回倒每次净亏一半，
  没有套利空间。
- tcr → 金币只允许花**临时余额**：`spendCredits(..., { temporaryOnly: true })`，
  临时余额不足则整笔拒绝，不会把永久充值余额换成游戏金币。
- 实现：金币 → tcr 是重放指令 `{ k: "bank", g }`（重放时扣金、累计 `bankedGold`，
  服务端结算时按 `bankCreditsForGold` 发 tcr）；tcr → 金币是服务端校验支付后追加的
  购买记录（`itemId` 为金币包，按 `cmdIndex` 在重放中入账），CAS 冲突自动退还 tcr。

## 反作弊与幂等

- **只收指令**：出城、购买、编成都记为命令数组，交卷时服务端从 `startSave` + 种子
  从零重放；客户端的金币、等级、战果一概不采信。指令经 `sanitizeSagaCommands` 清洗，
  未知字段、错槽装备、未上阵武将的动作全部丢弃。
- **局内购买**：服务端单独扣券并写入 `purchases`（带 `cmdIndex`），重放时从该步起生效，
  不会回溯加强已经开打的战斗；同一 `purchaseId` 幂等，CAS 失败自动退款。
- **只发一次**：收兵用 `UPDATE trial_run ... WHERE status = 'active'` 抢占；断网重试命中
  `already`，返回首次结果，不重复发奖。发奖失败把状态改回 `active` 让用户能重交。
- **旧局兼容**：答题 / 浮游城 / 横版动作（JSON 版本不是 6）的 `active` 局在开局时
  就地换成新行军，不重复扣券。
- 活动结束后仍可收兵：只要这行属于当前轮次（`activityKey` 为开始时间），按开局时的配置结算。

## 奖励与配置

默认 `questionCount = 5`、`runPriceCredits = 5`、券单价 `5 cr`，档位 2/3/4/5 节点 →
1/2/4/8 tcr，奖励 `rewardValidDays = 30` 天内有效。只有平定当前地方且未全剧终时发放。

后台可改每处地方节点数（2~7）、出城军令价、券单价、有效期与档位；
`tiers` 按节点数升序去重，超出节点数的档位由 `sanitizeTrialConfig` 丢弃。
