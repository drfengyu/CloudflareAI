# 限时活动·三国讨逆传（v0.60.0）

以《三国演义》为线索的长线剧情 RPG：从涿郡起兵，每处地方出城后是一张**类吞食天地的俯视行军
大地图**，四向自由走位、走到哪座营跟前就打哪座；拔尽此地营寨才出现下一处地名。战斗是回合制
兵团战（兵力、计策、阵型、招降），城里整备、编成、买卖装备。没有每日次数、没有限时——只有剧情推进。

- 前台：`/trial`（侧边栏入口「每日试炼」，页面标题「三国讨逆传」，活动中心默认展示）
- 后台：系统设置 → 「限时活动（每日试炼）」
- 配置键：`option.trial_config`（界面按字段拆成数字输入框，管理员不写 JSON）
- 引擎：`lib/trial/saga/`（存档归一、剧情数据、战斗 / 指令重放、行军结算）
  - `map.ts`：大地图生成（纯函数，按 `章节 + 营寨数 + 种子` 复现，不入库、不被采信）
  - `encounter.ts`：野外遭遇编成（按 `种子 + 第几场` 推出兵士 / 山贼 / 盗贼与可选敌将）
  - `training.ts`：训练场逐级训练（上限随平定数增长，券价按级差计）
  - `forge.ts`：铁匠铺装备强化（每件最多 +5 级，每级 +20% 基础属性，券价随等级递增）
  - `story.ts`：剧情场景（开场 / 阵前 / 平定 / 乡野 / 酒馆 / 议事）与城池 NPC 台词
  - `quests.ts`：军令（任务），进度从重放状态与乡野走访现算，不单独存档
- 渲染：`components/trial/renderer.ts`（俯视大地图与回合战斗两套 Canvas 像素场景，
  按 960×540 逻辑坐标绘制；战斗队列纵向排列，每名武将头顶一条按兵力上限分长短的血条
  与小签「名字 攻N 兵x/y」（v0.76.4 起画布顶部不再挂两军面板），
  指令与战报在画布下方独立排布；画布位图再按显示尺寸 × devicePixelRatio 放大，上限 2×，
  每帧 `setTransform` 复位，所以桌面宽版心与手机端都不会糊）；
  `components/trial/portraits.ts` 程序化武将立绘（按装备换装）
- 客户端：`components/trial/game.tsx`（行走与碰撞、城与营的交互、街景与店铺面板、
  剧情对话浮层、编成商店、回合战斗、行军续局）；`components/trial/scenes.tsx`
  承载街景 / 营地 / 对话浮层 / 军令与立绘组件
- 账本：`topup.type = 17`（钱庄存金在自动结算时折成 tcr，写成一条正流水；
  平定奖励直接加进剧情存档金币，不进 `topup`）；
  城内买卖（装备 / 药品 / 军需 / 客栈 / 训练 / 强化）在购买时按券扣费，写 `payWithCoupon` 的 type=15 支出；
  **钱庄金币换券**直接给 `activity_coupon` 加券面（与礼包兑换同一账本），不走 `topup`；
  **出城免费**，不按票价扣券
- 表：`trial_run`（迁移 `migrations/028_new_activity_games.sql`，沿用旧列：
  `questions` 存行军 JSON、`questionCount` = 营寨数、`correct` = 已攻破营寨数）

- 只有**拔尽当前地方的全部营寨**（自动结算时 `victory`）才会把存档推进到下一处；
  中途兵败不推进，可回城住店重整后接着走；撤退只结束当前战斗，行军继续。
- 没走到的地方在界面上只显示「？？？ / 未至」，剧情文本在进入该地时展示。
- 平定最后一处后 `campaignComplete` 为真，服务端拒绝再开新行军，界面显示「全剧终」。
- 存档（武将等级 / 装备 / 金币 / 已平定地方 / 图鉴）随最近一次结算的 `endSave` 延续，
  下次行军从该存档继续；已平定地方仍可重走练级，但**不再发平定奖励**。
  服务端取存档前把 `startedAt` 统一折成毫秒再排序（兼容历史上写成 ISO 文本的行），
  出城后一条指令都没落过的空壳行军不当作进度（详见「存档排序与空壳行军」）。

- **伤害与回复按兵力量级折算（v0.92.0）**：`battle.ts` 新增
  `forceDamage(rules, level, raw, targetLevel, factor, ratioFloor, ratioCeil)`——
  `rules >= 14` 时返回 `troopBaseline(level) × factor × clamp(raw / (67 + 1.7 × level)) × 等级差修正`
  （等级差修正钳 0.7~1.15），否则返回 `null` 走绝对值。接入点：
  普攻（我方 0.30 / 敌方 0.15）、计策伤害（我方 0.20 / 敌方 0.12，攻防比钳 0.05~3）、
  单体回复 0.16、全体回复 0.10；药品回复改成按目标兵力上限折算（军粮约一成、灵芝约两成，钳 4%~60%）。
  理由：兵力一百倍以后绝对值伤害会把一场仗拖成百回合；改口径后同等级对砍稳定五到八回合。
  另：`battleAttackPower(actor, rules)` 在 `rules >= 14` 时把敌军攻击力压到原式的 85%，
  「敌情」面板与战场名签同步显示该值——开局三将撞上五队兵时不至于每一下都比我们重。
- **敌军等级跟到 50 级（v0.92.0）**：`run.ts makeEnemy` 的等级从「每章 +4」改成

- **策略点随智力浮动**：

## 自动存档、撤退与训练场（v0.57.0）

- **自动存档**：客户端每产生一条指令（出战、结束战斗、购物、换阵、存金等），
  700 ms 防抖后把整段 `commands` 回传 `autoSaveTrialAction`；服务端 `saveTrialRunProgress`
  用整段行军 JSON 做乐观锁重放校验后写库。HUD 显示「存档中… / 已自动存档」。
  刷新页面时 `initialCommands` 取「本机 localStorage 指令」与「服务端指令」中更长的一份，
  本机进度领先（自动存档尚未追上）也不会被旧存档覆盖。
- **自动结算**：服务端在自动存档重放中发现 `scene === "won"`（此地营寨尽拔）时直接调用
  内部结算，返回 `settled` 与 `settlement`；客户端不再有「收兵」按钮，收到结果后清掉本机缓存、
  弹出结算卡。未平定就关页面不会结算，回来接着走。
- **撤退不是结束行军**：战斗中的「撤退」先追加本场已打的战斗块，再追加 `{ k: "retreat" }`；
  重放时 `retreatFromBattle` 把当前兵力写回队伍，还有人站着就回到 `field` 继续走，
  全军倒下才进入 `lost`。已攻克营寨、金币、经验、招降、装备全部保留，之前指令也不会丢。
- **训练场**：城中新增「训练场」铺面（NPC 周教头）。选武将、填目标等级，按
  `trainingCost(当前, 目标) = 级差 × 2 张券` 实时扣券，购买记录带 `generalId` / `targetLevel`；
  重放时 `trainGeneral` 把等级抬到目标值，`exp` 归零。上限 `trainingLevelCap` =
  `9 + 已平定地方数 × 3`，最高 30 级；超过上限的目标按上限处理，已在目标等级以上不收费。
- **军中一览**：行军大地图上点空白处（不撞营 / 乡野 / 城池）打开「军中一览」面板，
  逐将显示等级、四维、兵力条、经验、特性与已学计策，并列出上阵 / 后备、行囊道具、
  装备库存与队伍编制；战斗中点敌将立绘可直接设为目标。

## 存档完整性修复（v0.76.2）

- **空遭遇留档**：一回合没打就撤退的遭遇 `{ k: "skirmish", rounds: [] }` 不再被
  `sanitizeSagaCommands` 丢掉。遭遇编成按「本趟第几场」复现，丢掉空格会让之后所有野外

- **规则分界固定**：旧规则行军第一次读取时把补出来的 `rulesFrom` 立刻写回行军 JSON，

   - 走到敌营跟前开营地面板：敌将立绘与阵前喊话 + 战利品，选择「出战」或「自动战斗」切入回合制战斗。
   - 出城后官道、草地、海边滩涂与树林都会随机遇敌（见下节「野外遇敌」），
     只有城墙内与城门洞安全；遭遇战不占营地进度。
   - **攻打顺序由走位决定**：先打哪座营完全自由，只有主帅本阵要先拔尽其余营寨才肯出战
     （`canEngageNode`），其余营未清时打本阵的指令会被服务端丢弃且不会补打。
4. **城内买卖一律用活动券**（试炼券）：铁匠铺的武器护甲、药铺的伤药 / 良药 / 金疮药 / 大还丹、
   军需帐的局内增益（秘药 / 兵符 / 虎符 / 风行符 / 战鼓 / 锦囊）、客栈住店与训练场逐级训练
   都按商品券价在购买时实时扣券，购买记录带 `cmdIndex`，从下一步行动起生效；军需只在这次行军有效，
   被动军需每次限一份。v0.77.0 起铁匠铺多出七档兵器（环首刀 / 双戟 / 大斧 / 倚天剑 /
   丈八蛇矛 / 青龙偃月刀 / 方天画戟，攻 34~64、7~14 张券）和三档甲胄（鱼鳞甲 / 明光铠 /
   兽面吞头铠，防 30~46），药铺多出「军粮」（回 200 兵、2 券）与「灵芝」（回 450 兵、4 券）。
   名器只是价格更高的一档玩家装备，敌军配装仍走 `GEAR_TIERS` 的四档，旧战报不受影响。
   城中还有**活动券礼包**入口（兑换 / 购买后余额即时刷新），
   这是试炼券唯一的入口：v0.61.0 起 `/trial` 页面不再挂独立的券商店，券按画面内货币处理。
   **金币不能直接在铺子里买东西**：战斗缴获与平定奖励的金币可在钱庄存成 tcr
   （平定此地自动结算时到账），或按券面价换成试炼券当场使用（见下节）。
5. 战斗是五将回合制：
   - 每将每回合在战斗画面下方选 攻击 / 计策 / 防御 / 道具 / 招降；计策有火计、回复、混乱、鼓舞，
     消耗计策点，主将身负「无双 / 智圣 / 会心 / 猛将」等固有特性。
   - **双方最多 5 人上场**：玩家队伍上限 `SAGA_PARTY_SIZE = 5`；`rules >= 3` 的营寨 / 精锐 /
     攻城战会按种子随机补 1~N 个士兵位（`guard_<营>_<位>`，带兵器甲胄），
     连同敌将一起封顶 5 人，不会再出现一边六七个单位。
   - **敌情面板（v0.64.0，v0.66.0 带强化等级）**：战斗标题右侧新增「敌情」按钮，展开后逐名敌将显示
     等级、兵力、武力 / 智力 / 防御 / 速度 / 计策点、兵器与甲胄（含 `+N` 强化）及最终加成、计策与固有特性；
     点开不影响指令与动画，纯前端展示，不写入指令数组。
   - 阵型（v0.77.0 扩到 10 种）：鱼鳞 / 鹤翼 / 锋矢 / 方圆 / 长蛇 / 雁行 / 衡轭 / 背水 /
     八门 / 车悬，各改攻防速并互相克制。老五种的对位（鱼鳞克鹤翼、鹤翼克锋矢、锋矢克方圆、
     方圆克长蛇、长蛇克鱼鳞）保持不变，旧战报按原克制重放；新增五种各克一种老阵型：
     雁行克鱼鳞、衡轭克锋矢、背水克方圆、八门克鹤翼、车悬克长蛇。
     「背水」攻 +30% 防 -20%、「八门」防 +30% 攻 -5%，是两头的极端选择。
   - **野外招降（v0.76.10）**：招降只在野外遭遇里可用，营寨 / 精锐 / 攻城不再开放；
     野外头目随时可以劝降，成功率随其剩余兵力递减（满兵为 0，≤35% 时是原来的概率公式，
     吕布 / 张辽这类 `recruitHard` 额外 -25），队伍满时进后备。招降只收人，
     敌将随身的兵器甲胄不会带进队伍。
   - 战斗胜利得金币与经验，升级提升四维与兵力上限；计策点随智力与等级增长，智将在特定等级领悟新计策。
   - 全灭则兵败、全队兵力归零，行军退回「败退」状态：不能直接再出兵，要花 1 张试炼券住店重整；
     撤退只结束当前这一场，回到大地图接着走。进度每一步都会自动存档。
   - **指挥面板（v0.57.2）**：战斗指令区移到战场画布下方，不再压住两军血条；
     每名武将分「状态行 + 指令行」两行——名字 / 等级 / 兵力 / 计策点与当前指令在上，
     攻击 / 计策 / 防御 / 道具 / 招降按钮与目标、计策、道具选择在下，空间固定不换行。
6. 拔尽当前地方的全部营寨后，服务端在自动存档重放中判定 `victory`，**自动结算**并写回剧情存档，

   不再有手动「收兵」按钮，未平定就离开会保留进度。
   结算卡上的「回到城镇」只回城整备，剧情存档已经推进到下一处；不点「前往下一处」
   直接回城也不会丢进度，下次出发仍从新地方开始（v0.57.2 结算卡补充了这条说明）。

## 野外遇敌（v0.54.0，地形规则 v0.57.2）

`lib/trial/saga/encounter.ts` + `components/trial/game.tsx` 的逐格判定。

- **触发**：行走时每跨入一个新格子判定一次（`fieldEncounterChanceAt`）：
  官道 9%、草地 16.5%、海边滩涂 13.5%、树林 30%（v0.69.1 起为原概率的 3 倍）；
  城门洞、城墙与城内校场为 0。不设战后冷却，跨入新格子就会判定，
  边按键边走、点击寻路都会触发；触发即停下当前寻路，开遭遇战面板。
- **编成**：`sagaEncounterFor(run, ordinal, rules)` 只读 `run.seed` 与「本趟第几场」：
  兵种四选一（兵士守高、山贼攻高、海贼耐打、盗贼速高；v4 之前只有前三种），
  1~3 队杂兵，38% 概率由当前地方的
  敌将领头（合计最多 4 队）；等级、兵力、金币与经验随当前地方与场次成长。
  v0.76.6 起杂兵等级降为「章节 × 2 + 场次 / 3」（此前「章节 × 3 + 场次 / 2」），
  兵器甲胄比同级敌将**低两档**（`poor` 标记，v0.65 / v0.66 的行军仍低一档，见上节）；
  v0.76.10 起 v8 规则下野外头目都能劝降（黄巾力士这类通用杂号与杂兵仍不可招），
  且不再要求先压到 35% 血量；v7 及更早规则里野外敌军全部不可招降（v7 只放开了资料白名单里的头目）；
  胜利照常计入等级、金币、经验与图鉴。
- **不设场次上限**：一场接一场打都行，`encounters` 只用于按序号生成编成与战报统计，
  指挥令条数由既有的 `SAGA_MAX_COMMANDS` 兜底。战报记录 `encounters` 并在结算卡显示
  「野外遭遇 N 场」。
- **重放**：结束后上传 `{ k: "skirmish", rounds }`；服务端只在 `scene === "field"` 时受理，
  按同一序号重建敌军并逐回合重放。打赢回到 `field`（不占营地、
  不推进章节），打输进入 `lost`，与营寨战一样花 1 张试炼券住店重整。
  一回合没打就退的遭遇，旧版会留一条空战报以保持场次序号（v0.76.2 起客户端不再记录空遭遇，
  旧存档里的空格仍照常占一个场次）。
- **界面**：HUD 显示「遭遇 n 场」；遭遇战标题显示「敌军 N 队」。撤退会把本场已打的回合
  一起存档，只结束这一场遭遇，回到大地图继续行军；进度不会因此丢失。
- **遇敌地形（v0.57.2）**：出城后官道、草地、海边滩涂与树林都会遇敌——官道与海边沙岸
  不再安全，只有城门洞、城墙与城内校场（`SAGA_TILE_YARD`）不判定。营地 / 乡野点位
  扫出的空地只铺草地、保留已修好的官道（`paintBlob` 保留谓词）；渲染器会在水边画一圈
  沙岸与浪线，海边一眼可辨，但走上去照样可能撞见散兵、山贼、海贼与盗贼。

## 存档排序与空壳行军（v0.57.1）

- **`startedAt` 混排**：早期收尾分支用 `d1Run` 直接绑 `Date`，D1 HTTP 驱动会把参数
  JSON 化成 ISO 文本写进 INTEGER 列；SQLite 排序时 TEXT 恒大于 INTEGER，
  `ORDER BY startedAt DESC` 会把一条旧的兵败记录当成最新，于是平定后回到城镇一刷新，
  存档就被旧的 `endSave` 顶掉——等级、装备与购买全「回档」。
  `lib/trial/store.ts` 的 `startedAtDesc` 用
  `CASE WHEN typeof(startedAt) = 'text' THEN CAST(strftime('%s', startedAt) AS INTEGER) * 1000
  ELSE startedAt END` 统一按真实毫秒排序，读存档、找进行中行军、查历史记录共用；
  新的收尾分支也改为直接绑毫秒数。
- **空壳行军**：出城后没有落下任何 `commands`、没有 `purchases`、`shopSeq` 仍为 0 的行军
  （刷新 / 误关页面留下的）由 `sagaRunUntouched` 判定为没有进度，
  `findActiveTrialRun` 不把它当作进行中的行军；下一次「出发」走 `startTrialRun` 的旧行替换分支，
  按修正后的最新存档重开，不会把玩家卡在上一处地方。真正打过的行军（哪怕只有一次撤退）照旧续局。

## 经济：券流通、金币存 tcr 或换券（v0.55.0 / v0.58.0）

v0.55 起取消出城券费与金币商店：**活动券（试炼券）是城内唯一流通货币**，
金币只作为战斗缴获，在钱庄存成 tcr 或换成试炼券。

### 城内商店：全部按券计价

- 价目表在 `lib/trial/saga/data.ts`：武器 1/2/3/5 张、护甲 1/2/3/5 张、伤药 1 张、
  良药 2 张；军需 1~2 张。`SagaItemDef.priceTickets` 是唯一价格字段，
  服务端 `buyTrialItem` 按它乘券面单价 `couponUnitCredits` 扣券。
- 购买记录只存 `{ itemId, tickets, cmdIndex }`，重放时券价以商品表为准，
  客户端写回的张数不采信；被动军需每次限一份，客栈与消耗品可重复购买。
- 旧版金币商店指令 `{ k: "shop" }`、`{ k: "inn" }` 已从指令类型和
  `sanitizeSagaCommands` 中移除，改版后的客户端伪造也会被丢弃；
  历史行军里已落库的 `bank_gold` / `gold_*` 购买记录仍按旧价读回，不会丢账。

### 钱庄：金币 → tcr 或试炼券

存金规则写在 `lib/trial/saga/bank.ts`，汇率与单趟上限来自后台 `option.trial_config`，
**出城时冻结进本次行军**（`SagaRun.bank`），后台改价不影响在途存档；旧局没有
`bank` 字段时退回 `DEFAULT_SAGA_BANK`。换券汇率直接复用券面单价 `couponUnitCredits`
（1 张 = X cr 即 X 金/张），兑换时实时读取当前配置。

| 方向 | 比例 | 限制 | 到账时机 |
| --- | --- | --- | --- |
| 金币 → tcr | `bankGoldPerTcr`（默认 100 金 = 1 tcr） | 每次行军最多存 `bankMaxGoldPerRun`（默认 600 金） | 平定此地自动结算时折成 tcr 写入钱包，带 `rewardValidDays` 有效期 |
| 金币 → 试炼券 | 1 张 = `couponUnitCredits` 金（默认 5 金 = 1 张） | 不限量，只受手头金币与单笔 100,000 张上限约束 | 兑换即到账，同一趟行军马上能在城里花 |

- **数量自选**：钱庄面板两栏各一个数字输入框 +「全部」，实时显示折合 tcr / 张数与所需金币。
- **不再开放 tcr → 金币**：`SagaBankPolicy.goldPerTcrBuy` 只用于读回历史 `bank_gold`
  记录，不再出现在后台表单与页面上。
- **换券实现**：`buyTrialCoupons`（`lib/trial/store.ts`）先按客户端指令重放核对手头金币，
  再 `grantCouponToRound` 立即加券，然后把 `{ itemId: "coupon", coupons, goldCost, cmdIndex }`
  写进 `purchases`；重放侧 `applyPurchase` 只负责扣金币，券不入存档。
  写库用整段 JSON 乐观锁，失败时 `revokeCouponCredits` 撤回；同一 `purchaseId`
  重复提交直接返回当前状态，不会二次发券。
- **为什么不是 1 金 = 10 tcr**：一趟 5 座营全清给 `255 + 110×地方序` 金币，
  1:10 就是 2550 ~ 10250 tcr。默认存金收益 ≤ 6 tcr/趟，不会盖过战斗缴获本身的量级；
  按券面价换券则约 51~2050 张，和打一趟能花的券对得上。
- 实现：重放指令 `{ k: "bank", g }`（重放时扣金、累计 `bankedGold`，
  服务端结算时按 `bankCreditsForGold(gold, run.bank)` 发 tcr）。

### 铁匠铺：装备强化（v0.59.0）

铁匠铺除了卖兵器 / 甲胄，还能把已有装备逐级强化。规则写在 `lib/trial/saga/forge.ts`，
强化等级存进剧情存档的 `gearLevels`（按装备 ID 记 1~5 级，0 级不入表），
**与装备本身解耦**：换将、卸装、跨城镇换装都不掉级，下一趟行军直接从强化后的属性起算。

| 项 | 规则 |
| --- | --- |
| 上限 | `SAGA_FORGE_MAX_LEVEL = 5` |
| 属性 | 每级按基础属性的 20% 追加（四舍五入），满级约为原属性的两倍 |
| 券价 | `forgeCost(装备, 当前等级) = priceTickets + 当前等级 × 2`，满级返回 0 |
| 次数 | 一次一级，同一件装备可反复强化到满 |

- 强化作用于装备自带的攻击 / 防御：`generalStats(state, save.gearLevels)` 用
  `forgeStat` 算出武器攻击与护甲防御，战斗建阵时（`buildBattle`）与招降补兵都从这里取。
  敌方随机强化也走同一个 `forgeStat`，只是等级来自战斗种子而不是存档。
  不传等级表的旧调用（兵力上限、战力估算）保持原属性，不受影响。
- 服务端 `upgradeTrialGear`（`lib/trial/store.ts`）按客户端指令重放核对：装备必须在库存
  或已穿上、当前等级取自重放存档，**目标等级由服务端自己定**（当前 +1），客户端只报装备 ID。
  扣券走 `payWithCoupon`，购买记录 `{ itemId: "forge", gearId, targetLevel, tickets, cmdIndex }`
  写进行军 JSON；整段 JSON 乐观锁失败时退款，同一 `purchaseId` 重复提交只返回当前状态。
- 重放侧 `applyPurchase` 调 `upgradeGear` 只升不降（`Math.max`），伪造的低等级记录不会回退；
  `parsePurchases` 丢掉非装备 ID、零级与越界记录，`normalizeTrialSave` 把强化表截断到 0~5 级。
- 界面在「铁匠铺」面板下半区：列出库存与身上装备，显示当前等级、攻/防当前值 → 下一级值、
  下一级券价与「强化」按钮；满级显示「已满级」。

### 客栈：1 张券住一次

价格写死在引擎里：`SAGA_INN_PRICE_TICKETS = 1`（`lib/trial/saga/inn.ts`）。
结算重放不读后台配置，客户端与服务器必须同价，所以不做成可配置项。

- 住店走购买记录 `{ itemId: "inn_rest" }`：购买时 `buyTrialItem` 扣 1 张券，
  重放 `applyPurchase` 调 `restAtInn` 把上阵武将兵力补满。
- **兵败后也能住店**：`scene = "lost"` 时住店记录会把场景切回 `field`、清掉战败的
  `battle`，后续出兵 / 购物 / 钱庄指令重新生效；没有住店记录则仍困在败退状态。
  败退期间的战斗指令一律丢弃，避免零兵力白送。已破营寨不会回退。
- 兵力只存在于这次行军（`state.partyTroops`），结算后不带走；下次出城重新满编。
  所以客栈是「残兵撑到下一处 / 兵败后重整」的补给点，不是永久成长。
- 界面在「城中整备 → 客栈」页签：逐将显示当前 / 最大兵力与血条；
  住店按钮对场景做区分提示——满编显示「兵力已满」、券不足显示「活动券不足」、
  兵败后显示「全军败退 · 住店重整（1 张券）」并提示住店后可直接再战。
  敌营面板与军情面板的败退框里也有「回城住店」按钮，直接走到客栈。

## 画面与交互（v0.60.0）

- **动画时间基准**：帧循环里 `time` 是秒（环境动画用），`BattleAnimation.startedAt` 是
  `performance.now()` 毫秒。`paintBattle` 现在同时接收 `nowMs`，用
  `elapsed = max(0, nowMs - startedAt)` 算节拍；原先两者相减恒为负，`currentEvent` 永远为空，
  突刺 / 受击闪白 / 伤害飘字 / 计策特效都不会画，但按钮仍按事件数锁 1.2 秒以上。
  回合收尾的 `setTimeout` 存进 `animTimerRef`，开新回合或组件卸载时 `clearTimeout`。
- **点选敌将**：`battleEnemyAtPoint` 在 `unitSlots` 的命中框内取离触点最近的 slot。
  4 将以上时队列横向错位只有 40、命中框半宽 58，框必然重叠；按原顺序返回第一个会让玩家
  只能选中排在前面的敌将。点空地仍返回 -1。
- **手机开场卡**：画布容器 `overflow-hidden`，手机上画布高度约 `min(宽 × 4/3, 视口高 × 0.5)`，
  375×667 屏约 330px。开场卡片补 `max-h-full overflow-y-auto overscroll-contain`，
  内容超出时可滚动到「从城中出发」。
- **礼包确认**：`coupon-shop.tsx` 的礼包按钮只负责选中，下方确认条显示
  实付 cr / 到账张数，点「确认」才调用 `buyCouponPackAction`，取消不扣款。
- **忙碌口径**：交易请求进行中，所有铺子（装备 / 药铺 / 军需 / 铁匠铺 / 钱庄 / 客栈 / 训练场）

## 反作弊与幂等

- **只收指令**：出城、购买、编成、战斗、撤退都记为命令数组，服务端从 `startSave` + 种子
  从零重放；客户端的金币、等级、战果一概不采信。指令经 `sanitizeSagaCommands` 清洗，
  未知字段、错槽装备、未上阵武将的动作全部丢弃；`{ k: "retreat" }` 只在战斗场景生效。
- **自动存档**：`saveTrialRunProgress` 把整段 `commands` 与数据库里的行军 JSON 做乐观锁
  （`WHERE questions = ?`），每次都先重放校验再写回；客户端每 700 ms 防抖回传一次，
  刷新时优先采用本机与服务端中更长的一份指令，所以断电 / 关页面最多丢最后一步。
- **自动结算**：自动存档重放到 `scene === "won"` 时直接调用与手动交卷相同的
  `submitTrialRun`，靠 `UPDATE trial_run ... WHERE status = 'active'` 抢占，
  返回的 `settled` / `settlement` 让客户端清缓存并弹结算卡；没有「收兵」入口。
- **走位不入事实**：大地图的形状、营寨坐标、主角位置都是客户端按种子现算的，既不落库也不上传，
  所以「绕到营后」「走捷径」无法作弊。服务端只校验指令里的 `battle.node`
  （`canEngageNode`：下标合法、这座营还没破、主帅本阵必须先拔尽其余营寨）与
  `skirmish`（仅行军途中、场次不设上限）；非法指令整条丢弃，之后也不会被补打——
  因此客户端必须自己拦下非法出战。走哪条路、什么时候撞上敌人不影响任何数值，
  敌军编成由种子与场次推出；能改变结果的只有「打哪座营、打不打这场遭遇」和「这一仗怎么打」。
- **局内购买**：服务端单独扣券并写入 `purchases`（带 `cmdIndex`），重放时从该步起生效，
  不会回溯加强已经开打的战斗；同一 `purchaseId` 幂等，CAS 失败自动退款。
- **券余额即时可见**：城内活动券铺子的兑换与礼包付完就 `router.refresh()`；
  城内每次购买成功后用服务端返回的 `tickets` 更新本地余额，
  `components/trial/game.tsx` 在渲染期把 `initialTickets` 对齐进本地 state
  （与 `lottery-wheel.tsx` 同一写法），买完 / 刷新后按钮不会卡在旧余额。
- **只发一次**：自动结算 / 手动结算都用 `UPDATE trial_run ... WHERE status = 'active'` 抢占；
  断网重试命中 `already`，返回首次结果，不重复发奖。发奖失败把状态改回 `active` 让用户能重交。
- **旧局兼容**：答题 / 浮游城 / 横版动作（JSON 版本不是 6）的 `active` 局在开局时
  就地换成新行军；v0.56 及更早的讨逆传行军 `rules = 1`，按旧战斗规则重放；出城已免费，
  不存在补扣或退券。
- 活动结束后仍可自动结算：只要这行属于当前轮次（`activityKey` 为开始时间），按开局时的配置结算。

## 战斗演出与章节天候（v0.71.0）

- **伤害飘字**：`paintBattleFloats` 按 `events[i]` 的起始时间遍历整个动画窗口（`BATTLE_FLOAT_MS = 900`），
  不再只画 `currentEvent` 一条，所以一轮多段伤害 / 追击 / 火计能同时挂在空中逐条消散；

  `(events.length - 1) * stepMs + BATTLE_FLOAT_MS + 120`，最后一击的飘字也能播完。
- **打击手感**：震屏幅度由当前事件决定（败退 9 / 暴击 8 / 计策 5 / 普攻 3），

- **败退**：`down` 事件触发红印「败」砸落（1.8× → 1× 回弹）与脚下扬尘，持续 760ms；

- **倍速**：战斗指令行的 1× / 2× 只改 `stepMs = round(460 / speed)` 与 `playBattleSfx` 的间隔，

- **章节天候**：`SKY_MOODS` 为八处地方各存一套天空渐变、日轮、远山、薄雾、地面与官道颜色，

  `paintField` 在精灵画完后罩一层 `fieldTint` 环境色。
- **暴击标记**：`SagaBattleEvent.crit` 由 `dealDamage` 只写在普攻主事件上，
  是表现层字段，不参与重放校验，也不进存档。
